01How it worksSo funktioniert's

Cameras (or a recorder / VMS such as an Alnet NetStation) speak RTSP, which browsers cannot play. go2rtc pulls the streams and re-packages them as WebRTC without re-encoding – cheap on the CPU. go2rtc also serves the Cam2Wall dashboard, so there is only one process to run.

Kameras (oder ein Rekorder / VMS wie der Alnet NetStation) sprechen RTSP, das Browser nicht abspielen können. go2rtc holt die Streams ab und verpackt sie ohne Neukodierung als WebRTC – schonend für die CPU. go2rtc liefert außerdem das Cam2Wall-Dashboard aus, es läuft also nur ein Prozess.

02Quick startSchnellstart

On the first start the launcher downloads the pinned go2rtc release from the official GitHub releases, creates config/go2rtc.yaml from the example and – if openssl is available – a self-signed certificate.

Beim ersten Start lädt der Starter die festgelegte go2rtc-Version von den offiziellen GitHub-Releases, legt config/go2rtc.yaml aus der Vorlage an und – falls openssl vorhanden ist – ein selbstsigniertes Zertifikat.

# git clone https://github.com/30jannik06/Cam2Wall.git
cd Cam2Wall
start.bat

No git? Download the ZIP from GitHub, unpack it and double-click start.bat. Enter your camera URLs in the file that opens, then start again.

Kein git? ZIP von GitHub laden, entpacken und start.bat doppelklicken. Kamera-URLs in die geöffnete Datei eintragen und erneut starten.

git clone https://github.com/30jannik06/Cam2Wall.git && cd Cam2Wall
sh start.sh            # first run creates config/go2rtc.yaml – edit it, run again

The script detects your CPU (ARMv6 for the Pi Zero, ARMv7, ARM64, x64) and downloads the matching build. For autostart see Raspberry Pi.

Das Skript erkennt Ihre CPU (ARMv6 für den Pi Zero, ARMv7, ARM64, x64) und lädt die passende Version. Autostart: siehe Raspberry Pi.

cp config/go2rtc.example.yaml config/go2rtc.yaml   # edit your cameras
sh scripts/make-cert.sh                            # optional: HTTPS
docker compose up -d

The compose file uses host networking (Linux / Pi). On Docker Desktop (Windows/macOS) use the ports: block in docker-compose.yml and set webrtc.candidates to your PC's LAN IP.

Die Compose-Datei nutzt Host-Netzwerk (Linux / Pi). Unter Docker Desktop (Windows/macOS) den ports:-Block in docker-compose.yml verwenden und webrtc.candidates auf die LAN-IP des PCs setzen.

Then open http://localhost:1984 – or http://<IP>:1984 / https://<IP>:1985 from another device.

Danach http://localhost:1984 öffnen – oder von einem anderen Gerät http://<IP>:1984 / https://<IP>:1985.

03Add camerasKameras eintragen

Every stream in config/go2rtc.yaml becomes a tile, except names ending in _hd. Use the small sub stream for the grid and optionally an _hd twin that is loaded only while a camera is enlarged.

Jeder Stream in config/go2rtc.yaml wird eine Kachel – außer Namen mit der Endung _hd. Im Raster läuft der kleine Substream, optional gibt es einen _hd-Zwilling, der nur in der Einzelansicht geladen wird.

api:
  listen: ":1984"
  static_dir: "www"          # go2rtc serves the dashboard

streams:
  cam1:    "rtsp://USER:PASSWORD@SERVER_IP:554/video?device=vdrs&channel=0&stream=1"
  cam1_hd: "rtsp://USER:PASSWORD@SERVER_IP:554/video?device=vdrs&channel=0&stream=0"
  cam2:    "rtsp://USER:PASSWORD@SERVER_IP:554/video?device=vdrs&channel=1&stream=1"
Alnet NetStation: channel=0 is camera 1, channel=1 camera 2, and so on. stream=0 is the main stream, stream=1 the sub stream. channel=0 ist Kamera 1, channel=1 Kamera 2 usw. stream=0 ist der Hauptstream, stream=1 der Substream.

05Phone & networkHandy & Netzwerk

Phone and server must be on the same network. Open http://<server-IP>:1984 (the start script prints the IPs). Allow these ports in the firewall:

Handy und Server müssen im selben Netzwerk sein. http://<Server-IP>:1984 öffnen (das Startskript zeigt die IPs an). Diese Ports in der Firewall freigeben:

PortPurposeZweck
TCP 1984Dashboard + API (HTTP)Dashboard + API (HTTP)
TCP 1985Dashboard + API (HTTPS, self-signed)Dashboard + API (HTTPS, selbstsigniert)

Windows firewall

# PowerShell as Administrator
New-NetFirewallRule -DisplayName "Cam2Wall" -Direction Inbound -Action Allow -Profile Private -Protocol TCP -LocalPort 1984,1985,8555
New-NetFirewallRule -DisplayName "Cam2Wall UDP" -Direction Inbound -Action Allow -Profile Private -Protocol UDP -LocalPort 8555

HTTPS

Port 1985 uses a self-signed certificate created by scripts/make-cert.*. The browser warns once – choose "Advanced → Proceed". It is not needed for normal use, but some features of "installed" web apps prefer HTTPS.

Port 1985 nutzt ein selbstsigniertes Zertifikat von scripts/make-cert.*. Der Browser warnt einmal – „Erweitert → Trotzdem fortfahren" wählen. Für den normalen Betrieb ist es nicht nötig, manche Funktionen installierter Web-Apps bevorzugen aber HTTPS.

06Raspberry PiRaspberry Pi

  • Use sub streams in the grid (stream=1) – the biggest saving for Pi and Wi-Fi.
  • go2rtc does no transcoding for H.264 cameras, so the CPU mostly forwards packets.
  • A Pi Zero has 2.4 GHz Wi-Fi only; many parallel streams and viewers will saturate it. Prefer Ethernet/USB adapters if you can.
  • Streams pause automatically when a tab is hidden or a tile is out of view.
  • Monitor on the Pi? Pi OS Lite only shows a console. A browser kiosk (sh scripts/kiosk.sh) needs a CPU with NEON: Pi Zero 2 W, 3, 4, 5. The original Pi Zero / Zero W / Pi 1 (ARMv6) cannot run Chromium – use them as the server and open the dashboard on another device.
  • Im Raster Substreams nutzen (stream=1) – die größte Ersparnis für Pi und WLAN.
  • go2rtc transkodiert nicht bei H.264-Kameras, die CPU leitet überwiegend Pakete weiter.
  • Der Pi Zero hat nur 2,4-GHz-WLAN; viele parallele Streams und Zuschauer sättigen es. Wenn möglich Ethernet/USB-Adapter nutzen.
  • Streams pausieren automatisch, wenn der Tab verborgen oder die Kachel nicht sichtbar ist.
  • Monitor am Pi? Pi OS Lite zeigt nur eine Konsole. Ein Browser-Kiosk (sh scripts/kiosk.sh) braucht eine CPU mit NEON: Pi Zero 2 W, 3, 4, 5. Der originale Pi Zero / Zero W / Pi 1 (ARMv6) kann Chromium nicht ausführen – dort als Server nutzen und das Dashboard auf einem anderen Gerät öffnen.

Autostart (systemd)

sudo cp deploy/cam2wall.service /etc/systemd/system/
sudo nano /etc/systemd/system/cam2wall.service    # adjust User + paths
sudo systemctl enable --now cam2wall

07SecuritySicherheit

go2rtc's API has no login by default.Die go2rtc-API hat standardmäßig keine Anmeldung. Anyone who can reach port 1984/1985 can read the stream URLs including camera passwords (/api/streams). Jeder, der Port 1984/1985 erreicht, kann die Stream-URLs samt Kamera-Passwörtern auslesen (/api/streams).
  • Run it only on a trusted network, or enable a login:
  • Nur in einem vertrauenswürdigen Netz betreiben oder eine Anmeldung aktivieren:
api:
  username: admin
  password: change-me
  • Never expose the ports to the internet. For remote access use a VPN (WireGuard, Tailscale).
  • config/go2rtc.yaml, certs/ and bin/ are git-ignored – don't commit them.
  • Ports niemals ins Internet freigeben. Für Fernzugriff ein VPN nutzen (WireGuard, Tailscale).
  • config/go2rtc.yaml, certs/ und bin/ sind git-ignoriert – nicht committen.

08TroubleshootingProbleme lösen

The page looks old / a new feature is missing after an updateSeite wirkt alt / neue Funktion fehlt nach einem Update

go2rtc sends no cache headers for the dashboard files, so browsers may keep an older copy for a while. Do a hard reload: Ctrl+F5 (Mac: Cmd+Shift+R); on a phone clear the site data or reopen the page in a private tab.

go2rtc sendet für die Dashboard-Dateien keine Cache-Header, deshalb behalten Browser mitunter eine ältere Kopie. Hart neu laden: Strg+F5 (Mac: Cmd+Shift+R); am Handy die Websitedaten löschen oder die Seite in einem privaten Tab öffnen.

Tiles stay on "Connecting …" / "No signal"Kacheln bleiben auf „Verbinde …" / „Kein Signal"

Open the go2rtc console: errors for the stream URL show up there. Check IP, user/password and channel in config/go2rtc.yaml. Test the URL in VLC. On a phone, also check that TCP+UDP 8555 is allowed in the firewall.

go2rtc-Konsole ansehen: Fehler zur Stream-URL stehen dort. IP, Benutzer/Passwort und Kanal in config/go2rtc.yaml prüfen, die URL in VLC testen. Am Handy zusätzlich TCP+UDP 8555 in der Firewall prüfen.

Works on the PC, not on the phoneLäuft am PC, aber nicht am Handy

Use the PC's LAN IP (not localhost) and the same Wi-Fi. Allow ports 1984, 1985 and 8555 (see Phone & network). If the browser forces https://, use port 1985 and accept the certificate warning.

Die LAN-IP des PCs verwenden (nicht localhost) und das gleiche WLAN. Ports 1984, 1985 und 8555 freigeben (siehe Handy & Netzwerk). Erzwingt der Browser https://, Port 1985 nutzen und die Zertifikatswarnung akzeptieren.

go2rtc log: "request origin not allowed"go2rtc-Log: „request origin not allowed"

An old browser tab or bookmark opens the page from a different port or host than go2rtc. Open the dashboard directly at http://localhost:1984 and close old tabs.

Ein alter Tab oder ein Lesezeichen öffnet die Seite von einem anderen Port/Host als go2rtc. Das Dashboard direkt unter http://localhost:1984 öffnen und alte Tabs schließen.

"address already in use"„address already in use"

Another go2rtc (or program) already uses 1984/1985/8554/8555. start.bat stops old go2rtc processes itself; on Linux run pkill go2rtc or change the ports in the config.

Ein anderes go2rtc (oder Programm) belegt 1984/1985/8554/8555. start.bat beendet alte go2rtc-Prozesse selbst; unter Linux pkill go2rtc ausführen oder die Ports in der Config ändern.

HTTPS is not availableHTTPS ist nicht verfügbar

The certificate is created with openssl. Install it (Windows: it ships with Git for Windows) and run scripts/make-cert.ps1 / scripts/make-cert.sh. HTTP on port 1984 works regardless.

Das Zertifikat entsteht mit openssl. Installieren (Windows: ist in Git for Windows enthalten) und scripts/make-cert.ps1 / scripts/make-cert.sh ausführen. HTTP auf Port 1984 geht auch ohne.

The picture does not play at all / wrong codecBild läuft gar nicht / falscher Codec

Browsers play H.264 via WebRTC. H.265 (HEVC) cameras need transcoding in go2rtc (needs ffmpeg and a strong CPU – not a Pi Zero) or an H.264 stream setting on the camera. See the go2rtc documentation.

Browser spielen H.264 per WebRTC. H.265-(HEVC-)Kameras brauchen Transkodierung in go2rtc (ffmpeg und eine starke CPU – nichts für den Pi Zero) oder eine H.264-Einstellung an der Kamera. Siehe die go2rtc-Dokumentation.

Still stuck? Open an issue – and please remove passwords from logs.

Weiter ein Problem? Issue erstellen – bitte Passwörter aus Logs entfernen.
